# Plan project work

1. Follow [context resolution](../project-start/references/context.md). Read the notes CLAUDE.md, design, requirements, current tasks, and relevant decisions.
2. Inspect relevant implementation constraints before endorsing a design. Preserve the user's initial notes and distinguish supplied constraints, hypotheses, and unresolved questions.
3. Refine design.md with the problem, scope, proposed approach, and consequential alternatives. Ask focused questions only when their answers materially affect the work. Explain recommendations briefly.
4. Derive observable acceptance criteria in requirements.md, with stable R- IDs and explicit assumptions. Only label requirements confirmed when supported by supplied instructions or an actual agreement.
5. Break the agreed scope into bounded T- tasks with linked requirements, completion conditions, dependencies, and next actions. Keep existing IDs, status evidence, and completed history. Do not expand speculative future work into required tasks.
6. Record consequential adopted decisions and their provenance in decisions.md; identify proposals as proposals. Update progress.md with the planning outcome and current next action.
7. Summarize the plan and unresolved decisions. A planning request alone does not authorize implementation; if implementation is also requested, continue within the agreed scope.

Apply the notes update rules throughout this work, not just at its conclusion.
